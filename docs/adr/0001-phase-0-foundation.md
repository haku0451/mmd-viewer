# ADR 0001: フェーズ 0 の土台

## 状態

採用。この ADR のうち座標系の取り決めは、[ADR 0002](0002-left-handed-model-space.md) で置き換えた。

## 背景

MMD Viewer では、ファイル解析やアニメーションより前に、Windows アプリケーションの外枠が必要だった。リポジトリは hello-world のパッケージ 1 つから始まった。目標の構成には多くのクレートがあるが、中身のないクレートを作ると、未完成の機能があるように見えてしまう。

ビューポートには、明確な座標系の取り決めも 1 つ必要だった。glam、wgpu、PMX はクリップ空間の約束が同じではなく、軸の補正を描画コードのあちこちに散らすと、後からテストするのが難しくなる。

## 決定

Cargo ワークスペースを作り、フェーズ 0 で実際に使うクレートだけを置く。

- `mmd-core`: 共通の座標変換
- `mmd-editor`: 軌道カメラ
- `mmd-renderer`: wgpu の初期化、シーンのクリア、エディタのグリッド
- `mmd-telemetry`: tracing の設定
- `mmd-platform-windows`: 致命的エラーのダイアログ
- `apps/mmd-viewer`: winit と egui の統合

（当時）エディタの内部空間は右手系・Y 上とした。クリップ変換は `wgpu_clip_from_view` に置く。PMX 読み込み時の変換は、テストできるようになるまで保留する。→ この部分は ADR 0002 で左手系に置き換えた。

アプリのウィンドウは、まず Direct3D 12 のアダプタを要求する。失敗したら wgpu の主要なバックエンドで再試行し、エラーをログに残す。ビューポートの色バッファは、egui が画像として読めるよう `Rgba8Unorm` にする。この形式は統合上の制約であり、MMD の最終的な出力形式ではない。

MSVC ターゲットは `rust-toolchain.toml` で指定する。GitHub Actions は `windows-latest` で、整形、警告をエラー扱いにした Clippy、テスト、`cargo check` を実行する。

## 結果

- 以降のフェーズでは、機能が実際にできたときにクレートを追加する。
- エディタカメラは GPU なしでテストできる。描画は GPU デバイスなしでは単体テストできないため、自動テストの対象は CPU 側のグリッドと、リポジトリ内のシェーダーの検証になる。デバイスの作成は、`mmd-viewer` を起動して確かめる。
- 起動時、デバイスの作成中に一度だけ UI スレッドが止まる。バックグラウンドでの読み込みは別の要件として扱い、この起動経路をまねしない（現在、モデル・モーション・音声の読み込みは別スレッドで行っている）。
